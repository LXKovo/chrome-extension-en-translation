# 英文网页翻译 Chrome 插件 — 需求文档

## 1. 背景与目标

用户在日常浏览英文网站（技术博客、新闻、文档等）时，常常需要将整篇文章翻译为中文。市面上的整页翻译工具通常只能翻译 DOM 文本，无法保留文章结构、图片，也无法导出为便于二次编辑和分享的 Markdown 格式。

本插件旨在解决以下痛点：

- 一键提取当前页面的**主要文章内容**（正文），自动过滤导航栏、侧栏、广告、评论区等噪音。
- 将提取结果转换为结构清晰的 **Markdown** 格式，并保留原文中的**图片**。
- 调用**大语言模型（LLM）**进行高质量翻译（而非传统机器翻译）。
- 翻译结果以 **ChatGPT 打字机效果**逐字动态展示，提升阅读体验。
- 无需维护历史记录，仅在本地持久化保存**最近一次**翻译结果。

## 2. 目标用户

需要高效阅读英文长文、并希望以 Markdown 格式保存或二次整理翻译内容的浏览器用户，例如开发者、研究者、内容创作者等。

## 3. 运行环境

- 平台：Chrome 浏览器（含基于 Chromium 内核的浏览器）。
- 形态：浏览器扩展（Extension），通过工具栏图标或页面操作触发。

## 4. 功能需求

### 4.1 文章内容提取

- 用户在任意英文网页点击插件后，插件应能识别并提取该页面的**主要文章内容**。
- 提取范围包括：文章标题、作者、正文段落、列表、引用、代码块、图片等核心内容。
- 应尽可能排除与正文无关的元素：站点头部导航、侧边栏、页脚、广告、评论、相关推荐等。
- 提取策略需具备一定的通用性，能适配常见的英文站点（如 Medium、博客、新闻站点等）；对于无法识别的页面，应给出明确的失败提示。

### 4.2 Markdown 转换

- 提取后的文章内容需转换为 **Markdown 格式**。
- 图片需转换为 Markdown 图片语法：`![alt](src)`。
  - `alt`：优先使用图片的替代文本（alt 属性），缺失时使用合理的占位文本。
  - `src`：保留原始图片的 URL。
- 文章中的标题、加粗、斜体、列表、引用、代码块等结构应尽量在 Markdown 中保留对应格式。

### 4.3 大模型翻译

- 将转换为 Markdown 的原文内容作为输入，调用**大语言模型**进行翻译。
- 翻译目标语言为中文；输出保持 Markdown 结构（标题层级、列表、引用、图片等格式不变）。
- 插件需支持配置大模型服务（如 API 地址、API Key 等），由用户自行提供。
- **模型选择**：提供模型选择的选项，让用户从主流优秀大模型中选择，例如 `deepseek-v4-flash`、`deepseek-v4-pro`、`qwen` 等（具体列表以实现阶段确定的模型清单为准）。
- 翻译过程中应提供加载中状态，并对调用失败（网络错误、鉴权失败、额度不足等）给出可读的错误提示。

### 4.4 打字机效果展示

- 翻译结果需以类似 ChatGPT 的**打字机效果**动态、逐字展示。
- 展示过程中应提供停止/中断的能力，用户可随时终止展示。
- 打字机效果应尽量平滑，不阻塞页面主线程（避免卡顿）。

### 4.5 本地持久化存储

- **无需历史记录**：插件不维护翻译历史列表。
- 仅需在**本地**持久化保存用户**最近一次**的翻译结果。
- 用户在后续打开插件时，应能看到最近一次的翻译结果（例如作为默认展示或提供“查看上次结果”入口）。
- 存储位置为浏览器本地存储（如 `chrome.storage.local`），数据不上传、不跨设备同步。

### 4.6 最终输出格式

翻译完成后的最终输出内容，必须遵守以下统一格式：

```
# [文章标题]

> **作者**：[作者名]
> **原文链接**：[原始文章URL]

[翻译后的正文]
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| `[文章标题]` | 原文文章标题，翻译为中文 |
| `[作者名]` | 原文作者；若无法提取，使用 `xxx` 占位符取代 |
| `[原始文章URL]` | 当前页面的完整 URL |
| `[翻译后的正文]` | 翻译后的正文，保持 Markdown 结构（含图片语法） |

> 注：上方 `[ ]` 仅为占位符示意，最终以实际提取/翻译得到的内容为准。

## 5. 非功能需求

- **易用性**：用户操作路径尽量简短，理想情况下“一次点击”即可完成提取与翻译。
- **性能**：内容提取与 Markdown 转换应在本地快速完成；打字机展示不应引起页面明显卡顿。
- **隐私与安全**：API Key 等敏感配置仅存储在用户本地，不向外发送除翻译请求本身以外的数据。
- **兼容性**：适配常见英文站点；对无法提取或非英文页面有合理的降级与提示。
- **可维护性**：提取规则、翻译调用、展示逻辑等模块应相互解耦，便于后续扩展。

## 6. 范围界定（当前版本不包含）

- 翻译历史记录与多结果管理。
- 多语言互译（当前仅英文 → 中文）。
- 跨设备云同步。
- 导出为 PDF / Word 等非 Markdown 格式。
- 离线翻译。
