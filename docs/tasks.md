# 任务拆分

> 依据 `docs/proposal.md`（需求）、`docs/design.md`（架构）、`docs/layouts/`（页面布局）将实现工作拆分为独立可完成的任务。
> 每个任务均可单独完成并产出**可见效果**，依赖最小化，便于 AI 分步骤实现。

## 1. 优先级定义

| 优先级 | 含义 |
| --- | --- |
| **P0** | 核心链路（一键翻译 + 下载），MVP 必需 |
| **P1** | 体验完善（设置、持久化、状态/错误处理） |
| **P2** | 打磨与验收（可选优化） |

## 2. 任务总览

| ID | 任务 | 优先级 | 依赖 | 可见效果 |
| --- | --- | --- | --- | --- |
| T1 | 工程初始化：可加载的最小扩展 | P0 | — | Chrome 加载扩展，点图标弹空白 Popup |
| T2 | 主页面 UI 骨架与视图切换 | P0 | T1 | Popup 静态布局完整，主/设置视图可切换 |
| T3 | 内容提取与 Markdown 转换 | P0 | T1 | 拿到当前页面的 Markdown 原文 |
| T4 | 设置页表单与配置存储 | P0 | T2 | 可保存/读取 API 地址、Key、模型 |
| T5 | 翻译服务（Background 流式） | P0 | T4 | 流式获取大模型翻译增量 |
| T6 | 一键翻译主流程 + 打字机展示 | P0 | T2, T3, T5 | 点击按钮，结果逐字动态展示 |
| T7 | 下载 Markdown | P0 | T6 | 导出 `.md` 文件 |
| T8 | 结果持久化与恢复 | P1 | T6 | 重开 Popup 可见上次结果 |
| T9 | 状态流转与错误处理 | P1 | T6 | 各状态提示正确、错误可读、可停止 |
| T10 | 打磨与整体验收 | P2 | 全部 | 通过验收清单，整体可用 |

## 3. 任务详情

---

### T1 — 工程初始化：可加载的最小扩展

- **优先级**：P0
- **依赖**：无
- **涉及页面/模块**：无具体页面，全局工程
- **实现要点**：
  - 初始化 Vite + `@crxjs/vite-plugin` + React 19 + TypeScript 工程。
  - 配置 ESLint（typescript-eslint + react-hooks）、Prettier、husky + lint-staged、commitlint。
  - 编写 `manifest.json`（MV3；`storage`、`activeTab`、`scripting` 权限 + API 主机访问权限）。
  - 建立目录骨架 `src/{background, content, popup, shared}`，各入口有最小占位实现。
  - 在 `src/shared/` 定义消息名、存储键、类型与常量的初始版本。
- **完成标准 / 可见效果**：在 Chrome `chrome://extensions` 加载后，点击工具栏图标能弹出 Popup 页面（内容可为空白）。

---

### T2 — 主页面 UI 骨架与视图切换

- **优先级**：P0
- **依赖**：T1
- **涉及页面/模块**：[示意图-主页面.md](layouts/示意图-主页面.md) 的「顶栏 / 操作区 / 状态区 / 结果区」
- **实现要点**：
  - 按主页面布局搭建四个区域的静态结构：顶栏 Header（标题 + ⚙️设置入口）、操作区 ActionBar（模型下拉 + 一键翻译按钮 + 下载按钮）、状态区 StatusBar、结果区 ResultView。
  - 实现「主视图 / 设置视图」切换（设置视图先为占位）。
  - 引入 `md-wx` 依赖及样式，结果区可渲染一段**静态示例 Markdown**。
- **完成标准 / 可见效果**：打开 Popup 看到与布局图一致的静态页面，点击「设置」可切到设置占位视图，结果区能渲染示例 Markdown。

---

### T3 — 内容提取与 Markdown 转换

- **优先级**：P0
- **依赖**：T1
- **涉及页面/模块**：Content Script（`design.md` §4 提取链路）；结果区用于验证
- **实现要点**：
  - 内容脚本入口：监听消息并返回提取结果。
  - 提取链路：`Readability.parse()` → `DOMPurify` 净化 → 图片 URL 归一化（相对→绝对、懒加载 `data-src` 等）→
    `Turndown(+GFM)` 转 Markdown（图片转 `![alt](src)`）。
  - 输出 `{ title, author, url, markdown }`。
  - 定义/完善 `shared` 中的提取消息协议（请求/响应类型）。
- **完成标准 / 可见效果**：能对任意英文文章页拿到结构化 Markdown；通过临时展示（结果区或状态提示）可确认标题、作者、URL 与正文、图片语法正确。

---

### T4 — 设置页表单与配置存储

- **优先级**：P0
- **依赖**：T2
- **涉及页面/模块**：[示意图-设置页面.md](layouts/示意图-设置页面.md) 的「API 地址 / API Key / 默认模型 / 保存」
- **实现要点**：
  - 完成设置视图的表单：API 地址（预填 `https://api.deepseek.com`）、API Key（掩码 + 显示切换）、
    默认模型下拉（`deepseek-v4-flash` / `deepseek-v4-pro` / `qwen`）。
  - 读写 `chrome.storage.local` 的 `settings`（`baseURL` / `apiKey` / `model`）。
  - 保存校验（必填项、格式）与「保存后返回」、未保存改动确认。
  - 主页面操作区的模型下拉与设置页「默认模型」联动。
- **完成标准 / 可见效果**：设置页可填写并保存配置，刷新后配置仍在；主页面模型下拉与设置页保持同步。

---

### T5 — 翻译服务（Background 流式）

- **优先级**：P0
- **依赖**：T4
- **涉及页面/模块**：Background（`design.md` §5 翻译方案）；无独立 UI
- **实现要点**：
  - Background 消息路由 + `chrome.runtime.connect` Port 长连接。
  - OpenAI 兼容翻译客户端：`baseURL` + `model` + `apiKey` 可配，开启流式（SSE）。
  - 读取 `settings` 后发起流式翻译，将增量通过 Port 推送到 Popup。
  - 翻译输入为 Markdown 原文；Prompt 要求标题与正文译成中文、保持 Markdown 结构与图片语法不变。
- **完成标准 / 可见效果**：配置有效 API Key 后，能流式收到翻译增量（可临时在结果区展示原始流式文本验证连通性）。

---

### T6 — 一键翻译主流程 + 打字机展示

- **优先级**：P0
- **依赖**：T2、T3、T5
- **涉及页面/模块**：[示意图-主页面.md](layouts/示意图-主页面.md) 的「操作区（一键翻译）+ 结果区（打字机 + md-wx 渲染）」
- **实现要点**：
  - 点击「一键翻译」串联全流程：向 Content Script 提取 → 头部拼接（`# 标题` / `> 作者` / `> 原文链接`）→ 交由 Background 流式翻译。
  - 结果区：流式增量 → 逐字缓冲（字符队列）→ 增长 Markdown 字符串 → `md-wx` 的 `<MarkdownRenderer>` 动态渲染，实现逐字打字机效果。
  - 翻译中提供「停止」能力；翻译中禁用「一键翻译」避免重复触发。
- **完成标准 / 可见效果**：在英文文章页点击一键翻译，结果区先显示头部、正文逐字打出，最终输出符合需求文档统一格式。

---

### T7 — 下载 Markdown

- **优先级**：P0
- **依赖**：T6
- **涉及页面/模块**：[示意图-主页面.md](layouts/示意图-主页面.md) 的「操作区（下载按钮）」
- **实现要点**：
  - 将当前最终 Markdown 字符串导出为 `.md` 文件（Blob + 触发下载）。
  - 文件名使用文章标题（或时间戳兜底）。
  - 无结果时「下载」按钮禁用（置灰）。
- **完成标准 / 可见效果**：翻译完成后点击「下载」，得到内容正确的 `.md` 文件；无结果时按钮不可点。

---

### T8 — 结果持久化与恢复

- **优先级**：P1
- **依赖**：T6
- **涉及页面/模块**：[示意图-主页面.md](layouts/示意图-主页面.md) 的「结果区（上次结果）」
- **实现要点**：
  - 翻译完成后将最终 Markdown + 元数据（`title / author / url / timestamp`）写入 `chrome.storage.local` 的 `lastResult`。
  - 打开 Popup 时加载 `lastResult` 并默认展示，状态区显示「上次翻译于 …」。
  - 不维护历史列表。
- **完成标准 / 可见效果**：翻译后关闭再打开 Popup，上次结果仍在，可直接查看或下载。

---

### T9 — 状态流转与错误处理

- **优先级**：P1
- **依赖**：T6
- **涉及页面/模块**：[示意图-主页面.md](layouts/示意图-主页面.md) 的「状态区 StatusBar / 结果区空态」
- **实现要点**：
  - 统一状态机：空闲 / 提取中 / 翻译中 / 完成 / 错误，状态区文案随状态切换。
  - 错误可读化：无法识别正文、网络错误、鉴权失败、额度不足等给出明确提示。
  - 错误时不覆盖已有结果；首次使用空态引导（未配置 Key 时引导进入设置页）。
- **完成标准 / 可见效果**：各流程阶段状态提示正确；模拟错误（如无效 Key）能看到可读错误，且已有结果不被清空。

---

### T10 — 打磨与整体验收

- **优先级**：P2
- **依赖**：全部
- **涉及页面/模块**：主页面、设置页面整体
- **实现要点**：
  - 走查布局与需求文档，修复细节（按钮禁用态、加载态、空态、文案一致性）。
  - 验证核心流程在常见英文站点可用。
  - 通过 ESLint/Prettier 检查，确保无 TS 错误。
- **完成标准 / 可见效果**：满足需求文档全部功能，通过下方验收清单。

## 4. 依赖关系图

```text
T1 工程初始化
 ├─▶ T2 主页面骨架 ──────────────┐
 ├─▶ T3 内容提取 ────────────────┤
 └─▶ T4 设置与存储 ─▶ T5 翻译 ───┤
                                  ▼
                               T6 主流程+打字机
                                  ├─▶ T7 下载
                                  ├─▶ T8 持久化
                                  ├─▶ T9 状态/错误
                                  └─▶ T10 打磨验收
```

- **可并行**：T2、T3、T4 互不依赖，可在 T1 完成后并行推进。
- **关键路径**：T1 → T4 → T5 → T6 → (T7 / T8 / T9) → T10。

## 5. 验收清单（T10 依据）

- [ ] Chrome 可加载扩展，点击工具栏图标弹出 Popup。
- [ ] 在英文文章页点击「一键翻译」，能提取正文并逐字展示中文翻译。
- [ ] 输出格式符合需求文档（标题 / 作者 / 原文链接 / 正文）。
- [ ] 图片以 `![alt](src)` 形式保留。
- [ ] 翻译结果可下载为 `.md` 文件。
- [ ] 设置页可配置 API 地址、Key、模型，且持久化保存。
- [ ] 关闭再打开能看到最近一次翻译结果。
- [ ] 各状态与错误提示可读，翻译中可停止。
