# 实现步骤与页面规划

> 依据 `docs/proposal.md` 与 `docs/design.md`，将插件拆分为 2 个页面、若干功能模块，并按依赖顺序规划实现步骤。页面布局详见同目录下的 `示意图-*.md` 文件。

## 1. 页面清单

| 页面 | 布局文件 | 职责 | 触发方式 |
| --- | --- | --- | --- |
| 主页面（侧边栏） | [示意图-主页面.md](示意图-主页面.md) | 一键翻译、下载、结果展示（打字机 + md-wx 渲染） | 点击工具栏图标（右侧 `chrome.sidePanel` 打开） |
| 设置页面 | [示意图-设置页面.md](示意图-设置页面.md) | 配置 API 地址、API Key、默认模型 | 主页面顶栏「设置」入口 |

> 设计原则：**简约、少功能、突出「一键翻译」与「下载」**。设置项收拢到独立的设置页面，主页面只保留高频操作。

## 2. 页面 — 功能 — 模块划分

```text
插件（Chrome Extension）
├── 主页面（侧边栏）
│   ├── 顶栏 Header          ← 标题 + 设置入口
│   ├── 操作区 ActionBar     ← 模型选择 + 一键翻译 + 下载
│   ├── 状态区 StatusBar     ← 空闲 / 提取中 / 翻译中 / 完成 / 错误
│   └── 结果区 ResultView    ← md-wx 渲染 + 打字机 + 空闲态/上次结果
└── 设置页面（Settings）
    ├── 顶栏 Header          ← 返回 + 标题
    ├── API 地址输入
    ├── API Key 输入
    ├── 默认模型选择
    └── 保存按钮 + 隐私说明
```

## 3. 实现步骤（按里程碑）

实现顺序遵循「先骨架、后能力、再打磨」，依赖关系自上而下。

### M0 — 工程初始化

| 内容 | 说明 |
| --- | --- |
| 脚手架 | Vite + `@crxjs/vite-plugin` + React 18 + TypeScript |
| 工程规范 | ESLint（typescript-eslint + react-hooks）、Prettier、husky + lint-staged、commitlint |
| 清单 | `manifest.json`（MV3；`storage`、`activeTab`、`scripting`、`sidePanel` 权限 + `side_panel.default_path` + API 主机访问权限） |
| 目录 | 搭建 `src/{background, content, sidepanel, shared}` 结构 |
| 共享层 | `src/shared/` 定义消息协议、类型、常量、存储键 |

**产出**：可加载的最小扩展（空白侧边栏页面）。

### M1 — 主页面骨架

| 内容 | 涉及模块 |
| --- | --- |
| 侧边栏布局与「主视图 / 设置视图」切换 | 顶栏 |
| 操作区、状态区、结果区组件骨架 | ActionBar / StatusBar / ResultView |
| 引入 `md-wx` 依赖与样式 | ResultView |

**产出**：主页面静态布局可见，结果区可渲染一段静态 Markdown。

### M2 — 内容提取（Content Script）

| 内容 | 涉及模块 |
| --- | --- |
| 内容脚本入口 + 消息响应 | Content Script |
| Readability 提取 → DOMPurify 净化 → 图片 URL 归一化 → Turndown 转 Markdown | extractor |
| 降级与失败提示（无法识别 / 非英文） | StatusBar |

**产出**：点击「一键翻译」能拿到当前页面的 Markdown 原文。

### M3 — 翻译（Background）

| 内容 | 涉及模块 |
| --- | --- |
| OpenAI 兼容翻译客户端（`baseURL` + `model` 可配、流式） | translator |
| 消息路由 + `chrome.runtime.connect` Port 流式推送 | Background |
| 读取设置（API 地址 / Key / 模型） | storage |

**产出**：能流式获取大模型翻译增量。

### M4 — 打字机展示与渲染

| 内容 | 涉及模块 |
| --- | --- |
| 逐字缓冲区（字符队列）+ 停止控制 | ResultView |
| 流式增量 → 增长 Markdown 字符串 → `md-wx` 动态渲染 | ResultView |
| 头部（标题 / 作者 / 原文链接）拼接 | ResultView |

**产出**：翻译结果以打字机效果逐字展示。

### M5 — 本地持久化

| 内容 | 涉及模块 |
| --- | --- |
| 写入 / 读取 `lastResult`（最终 Markdown + 元数据） | storage |
| 打开侧边栏时加载上次结果 | ResultView |
| 保存 `settings`（设置页） | 设置页面 |

**产出**：关闭再打开能看到最近一次翻译结果。

### M6 — 下载、设置页与打磨

| 内容 | 涉及模块 |
| --- | --- |
| 「下载 Markdown」导出 `.md` 文件 | ActionBar |
| 设置页表单（地址 / Key / 模型）与保存、校验 | 设置页面 |
| 错误提示统一、空态 / 加载态 / 完成态完善 | StatusBar / ResultView |

**产出**：满足需求文档全部功能的可用插件。

## 4. 依赖关系

```text
M0 工程初始化
   └─▶ M1 主页面骨架 ──▶ M4 打字机展示（依赖 M3 的流式数据）
   └─▶ M2 内容提取 ──▶ M3 翻译 ──▶ M4 ──▶ M5 持久化 ──▶ M6 下载/设置/打磨
```

- M1、M2 可并行开发（骨架与提取互不阻塞）。
- M4 依赖 M3；M5、M6 依赖 M4。
